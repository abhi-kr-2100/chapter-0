Architectural Blueprint v1.0

Chapter 0 — Architecture Overview

A high-performance, local-first document reader built as a Progressive Web App (PWA) using the Origin Private File System (OPFS) and web worker threading.

1. Core Architectural Pillars

Local-First & Zero-Knowledge

Books are parsed, rendered, and stored entirely within the client's browser sandbox. User libraries are never uploaded to a cloud server, ensuring absolute privacy, zero bandwidth costs, and offline-by-default execution.

Native-Class I/O with OPFS

By leveraging the Origin Private File System (OPFS) and its synchronous access handles inside Web Workers, the reader bypasses IndexedDB serialization overhead and reads gigabyte-scale PDFs with zero memory pressure.

OS-Integrated PWA

Using the File Handling API, Web Share Target, and Storage Persistence API, Chapter 0 bridges the gap between browser sandbox and desktop/mobile operating systems.

Non-Blocking Worker Pipeline

All file decompression (ZIP/EPUB), PDF stream parsing, full-text indexing, and texture rasterization run off the main thread to ensure uninterrupted 120Hz gesture navigation and page turns.

2. High-Level System Topology

The system is divided into four distinct execution layers designed to keep UI responsiveness isolated from heavy document processing and disk I/O.

Layer 1: OS & Browser Integration Layer (PWA Capabilities)

File Handling API

Registers .epub and .pdf file associations on Windows, macOS, and ChromeOS via launchQueue.

Service Worker

Pre-caches core app shell, fonts, and WebAssembly bundles using a Cache-First offline strategy.

Web Share Target

Receives shared books directly from native mobile share sheets on Android and supported web browsers.

3. Deep Dive: Origin Private File System (OPFS)

Traditional browser readers store books as Base64 strings or binary Blob objects inside IndexedDB. This causes severe memory spikes, UI stutters during serialization, and frequently crashes on mobile Safari when handling 50MB+ textbooks.

Chapter 0 solves this by using OPFS as a high-performance virtual hard drive:

Feature IndexedDB Blobs (Conventional) Origin Private File System (OPFS)
I/O Model Asynchronous, passes entire blob copies across thread boundaries. True byte-range streaming via FileSystemSyncAccessHandle.
Memory Footprint Entire file often loaded into RAM; causes OOM on mobile. Reads only the requested chunk/page directly from disk.
Access Location Main thread or worker with async transaction overhead. Synchronous high-speed read/write inside dedicated Web Workers.
File Organization Flat key-value store. Hierarchical directory structure mimicking a real file system.

OPFS Directory Layout

/ [root OPFS directory]
├── books/
│   ├── book_a8f9c1/
│   │   ├── raw.bin           # Original immutable PDF/EPUB bytes
│   │   └── cover.webp        # Extracted thumbnail
│   └── book_3d21b4/
│       ├── raw.bin
│       └── cover.webp
└── cache/
    └── tiles/                # Pre-rasterized page textures for instant swiping

High-Speed Worker OPFS Streaming Pattern

// Inside storage.worker.js
async function readBookChunk(bookId, offset, length) {
  const root = await navigator.storage.getDirectory();
  const booksDir = await root.getDirectoryHandle('books');
  const bookDir = await booksDir.getDirectoryHandle(bookId);
  const fileHandle = await bookDir.getFileHandle('raw.bin');

  // Fast synchronous access handle (Workers only)
  const accessHandle = await fileHandle.createSyncAccessHandle();
  const buffer = new ArrayBuffer(length);
  
  accessHandle.read(buffer, { at: offset });
  accessHandle.close();

  return buffer; // Zero-copy transferable array buffer
}

4. Deep Dive: Progressive Web App (PWA) Capabilities

To deliver an experience indistinguishable from native apps, Chapter 0 exploits three critical modern PWA standards:

A. File Handling API (Double-Click OS Association)

On supported platforms (Windows, macOS, ChromeOS), Chapter 0 registers itself as an authorized system handler for .epub and .pdf. When a user double-clicks an ebook in their desktop file manager, the OS boots Chapter 0 and feeds the file handle directly to the app.

// manifest.webmanifest
{
  "name": "Chapter 0",
  "display": "standalone",
  "file_handlers": [
    {
      "action": "/reader",
      "name": "E-Book Document",
      "accept": {
        "application/epub+zip": [".epub"],
        "application/pdf": [".pdf"]
      }
    }
  ]
}
// Main thread consumer: app.js
if ('launchQueue' in window) {
  window.launchQueue.setConsumer(async (launchParams) => {
    for (const fileHandle of launchParams.files) {
      const file = await fileHandle.getFile();
      await importBookToOPFS(file);
    }
  });
}

B. Storage Eviction Protection (Persistence API)

Browsers automatically delete origin data when disk space is tight unless origin persistence is explicitly granted. Chapter 0 prompts for persistent storage upon adding the first book.

async function ensurePersistentStorage() {
  if (navigator.storage && navigator.storage.persist) {
    const isPersisted = await navigator.storage.persisted();
    if (!isPersisted) {
      const granted = await navigator.storage.persist();
      console.log(`Storage persistence granted: ${granted}`);
    }
  }
}

5. Storage Separation: OPFS vs. IndexedDB

To achieve instantaneous library browsing while handling heavy binary payloads, data is cleanly segregated:

Origin Private File System (OPFS)

Role: Raw Binary Storage

  • Original .epub and .pdf binaries.
  • Unzipped chapter XML documents (cached on demand).
  • Extracted embedded fonts and raster images.
  • Pre-rendered page bitmap caches.

IndexedDB (Key-Value Database)

Role: Structured Metadata & State

  • Book Catalog: Title, author, ISBN, date added, file size, OPFS path.
  • Reading Progress: Current EPUB Canonical Fragment Identifier (CFI) or PDF page index.
  • Annotations: Highlights, color tags, user notes, and timestamps.
  • Typography Settings: Font family, scale factor, margin widths, color schemes.

6. Path to Ubiquity: Progressive Expansion

  1. Phase 1 (MVP — Hosted PWA): Instant web access via static CDN, OPFS storage, Service Worker offline caching, and PWA manifest.
  2. Phase 2 (OS Store Presence): Package the identical PWA codebase using Tauri v2 (desktop macOS/Windows/Linux) and Capacitor (iOS & Android) to gain full OS file associations and store discoverability.
  3. Phase 3 (Zero-Knowledge Metadata Sync): Implement end-to-end encrypted sync (using CRDTs or lightweight WebSockets) to sync bookmarks, reading positions, and highlights across devices without needing heavy cloud book storage.
